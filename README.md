# Aetheris Character Forge

Aetheris Character Forge is a deterministic fantasy RPG character generator built as a React single-page app. A character can be regenerated from the same seed and name, then explored through profile, lore, world, mechanics, skills, inventory, vault, stable, and bestiary-oriented views.

The app is frontend-only. There is no backend service, database, Docker setup, or committed environment file in this repository.

## Quick Start

Use Node.js with npm. The GitHub Pages workflow uses Node 22, so Node 22 is the safest local version for parity.

```bash
npm ci
npm run dev
```

Vite prints the local development URL after startup. By default this is usually `http://localhost:5173/`.

## Configuration

No required environment variables are visible in the current codebase.

Important runtime/build details:

- Routing uses TanStack Router with hash history, so production URLs are hash-based.
- `src/routeTree.gen.ts` is generated by TanStack Router and should not be edited manually.
- `vite.config.ts` sets `base: './'` for static hosting and GitHub Pages compatibility.
- `vite.config.ts` also defines manual chunks for large generated-data areas and allows two specific dev tunnel hosts through `server.allowedHosts`.
- Generated characters are not persisted as full records. The app reconstructs them from route seed/name data.
- Local UI preferences such as theme, density, motion, scale, and panel sub-tabs are stored in `localStorage`.

## Architecture Overview

### Generation Flow

Routes call the character store in `src/store/characterStore.ts`. The store dynamically imports `src/lib/generator.ts`, which constructs the character using domain engines in `src/logic/`.

The generation flow is seed-driven and should remain deterministic for the same input. Shared random utilities live in `src/lib/randomUtils.ts`; prefer direct utility imports where possible so UI code does not accidentally pull the full generator into initial bundles.

### UI Flow

The main character experience is composed from `src/components/Layout/ProfileLayout.tsx` and tabbed panels. Heavier route and panel areas are lazy-loaded with `React.lazy` and `Suspense`.

Common UI patterns include:

- `src/components/ui/SecondaryTabs.tsx` for keyboard-accessible sub-tabs.
- `src/hooks/usePersistedTab.ts` for remembering local panel tab choices.
- `src/components/ui/PanelSearch.tsx` for panel-local filtering and count display.
- `src/lib/generatedEntryUtils.ts` for shared filtering and generated-entry metadata helpers.

### Inventory and Stable

Inventory UI lives mostly under `src/components/Inventory/`. Vault, crafting, and stable panels are lazy-loaded from `InventoryPanel`.

Inventory placement and movement use centralized slot definitions in `src/data/inventory/slots.ts` and request validation in `src/logic/InventoryMoveEngine.ts`. Bestiary-backed companions and mounts are surfaced through the stable UI rather than as standalone routes.

### Data and Config

Static generator data is stored as TypeScript modules under `src/data/`. Generator tuning and validation helpers live under `src/config/`. Keep new generated-data additions close to their domain folder so chunking and ownership stay predictable.

## Testing

Tests use Vitest with jsdom. Test setup is configured in `vitest.config.ts` through `test/setup.ts`.

Run the full test suite with:

```bash
npm test
```

For UI changes, add focused component tests where behavior is stateful, keyboard-driven, or easy to regress. Existing examples are under `test/components/`.

## Build and Deploy

Build locally with:

```bash
npm run build
```

The production output is written to `dist/`.

GitHub Pages deployment is configured in `.github/workflows/deploy.yml`. On pushes to `main` or manual workflow dispatch, CI uses Node 22, runs `npm ci`, `npm run lint`, and `npm run build`, then uploads `dist/` to Pages.

## Contributor Notes

- Project governance and release notes live in [LICENSE.md](LICENSE.md), [CHANGELOG.md](CHANGELOG.md), and [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
- Keep React UI concerns in `src/components/`, hooks in `src/hooks/`, and generation/business logic in `src/logic/` or `src/lib/`.
- Do not edit `src/routeTree.gen.ts` manually.
- Keep generated-data files deterministic and side-effect light.
- Use existing shared controls before creating another panel-specific variant.
- Update tests when changing generation behavior, inventory movement, route behavior, persisted tabs, or keyboard interaction.
- Avoid adding dependencies unless the repository's current React/Vite/TypeScript stack cannot reasonably handle the task.

## Troubleshooting

- If a direct production URL does not resolve as expected, use the hash route form because the app uses hash history.
- If local development needs a different port, run `npm run dev -- --port 5174`.
- If a tunnel host is blocked by Vite, check `server.allowedHosts` in `vite.config.ts`.
- If TypeScript or Vite fails on an older Node version, retry with Node 22 to match CI.
- If generated routes appear stale after route file changes, restart the dev server so the TanStack Router Vite plugin can regenerate the route tree.
