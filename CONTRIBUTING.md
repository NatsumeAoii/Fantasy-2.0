# Contributing to Aetheris Character Forge

Contributions are welcome. This document covers expectations for code, pull requests, and collaboration.

---

## Prerequisites

- Node.js 22+ (matches CI)
- npm (comes with Node)
- Git

---

## Getting Started

```bash
git clone https://github.com/NatsumeAoii/Aetheris-CharGen.git
cd Aetheris-CharGen
npm ci
npm run dev
```

Verify everything works:

```bash
npm run lint
npm test
npm run build
```

---

## Development Workflow

1. Create a branch from `main` with a descriptive name: `feat/vault-sorting`, `fix/seed-overflow`, `docs/readme-qa`.
2. Make your changes in small, focused commits.
3. Run lint and tests before pushing:
   ```bash
   npm run lint
   npm test
   ```
4. Open a pull request against `main`.

## Code Organization Rules

| Concern | Location |
| --- | --- |
| React UI components | `src/components/` |
| Reusable hooks | `src/hooks/` |
| Generation engines and business logic | `src/logic/` |
| Shared utilities (PRNG, clipboard, rarity) | `src/lib/` |
| Zustand stores and state | `src/store/` |
| Static generation data | `src/data/` |
| Generator config and tuning | `src/config/` |
| TypeScript interfaces | `src/types/` |
| Tests | `test/` (mirrors `src/` structure) |

---

## Code Style

- **TypeScript strict mode** is enforced. No `any` without justification.
- **ESLint** is configured for React + TypeScript. Run `npm run lint` and fix issues.
- **Tailwind CSS 4** via PostCSS. Use utility classes. Design tokens are in `src/styles/theme.css`.
- **Single quotes** for strings in data files. Escape apostrophes with `\'`.
- **IDs**: `snake_case`. **Names**: `Title Case`.
- Follow existing patterns. If the codebase does something one way, do it that way.

---

## Data Contributions

If adding to `src/data/`, follow the rules in `.workRules/dataRules.md`:

- High-fantasy medieval theme only. No modern, sci-fi, or real-world terms.
- Use Aetheris terminology (not D&D). See the Terminology Standard in `dataRules.md`.
- All descriptions: max 150 characters, no adverb stacking, unique within their group.
- Tiered data: exactly 6 tiers, monotonically increasing prices/stats, 1.5x–3x ratio between adjacent tiers.
- Variant counts must match the standard for that data type.
- IDs and names must not duplicate existing entries.
- Run `npx tsc --noEmit` after data changes to verify the build passes.

## Testing Expectations

- Add tests when: changing generation behavior, inventory movement, route behavior, persisted tab logic, or keyboard interaction.
- Tests live in `test/` mirroring the `src/` structure.
- Use Vitest + React Testing Library.
- Test the behavior, not the implementation. Focus on what a user or consumer observes.
- Existing test examples are the style guide — follow them.

---

## Generated Files

Do **not** edit these manually:
- `src/routeTree.gen.ts` — Generated by TanStack Router Vite plugin on dev server start.

---

## Commit Messages

Use clear, descriptive commit messages. Prefer the imperative mood:

- `Add vault sorting by rarity`
- `Fix seed overflow at 512 characters`
- `Remove unused ShieldIcon import`

No strict conventional commit format is enforced, but keeping messages scannable helps reviewers.

---

## Pull Request Guidelines

- Keep PRs focused. One feature or fix per PR.
- Include a brief description of what changed and why.
- If the change affects generation output (different characters from the same seed), note this explicitly — it's a breaking change.
- If adding new data domains, update the manual chunks in `vite.config.ts` if the file is large enough to warrant its own bundle.
- Ensure CI passes (lint + build). Tests run locally since CI does not currently execute them.

---

## Architecture Decisions

Significant architectural choices are documented in `docs/decisions/` as ADRs. If your contribution introduces a new pattern, dependency, or structural change, consider adding an ADR.

---

## What Not to Do

- Do not add dependencies without strong justification. The current React/Vite/TypeScript/Zustand/TanStack Router stack handles most needs.
- Do not introduce circular dependencies between modules.
- Do not add tiers 7–8 to static data files. Those are runtime-only.
- Do not use emoji or Unicode symbols as UI icons. Use `react-icons` components.
- Do not hardcode personal tunnel hostnames in `vite.config.ts`.
- Do not commit `.env` files, secrets, or personal configuration.
