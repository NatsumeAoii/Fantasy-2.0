# Code of Conduct

## Purpose

Aetheris Character Forge should be practical to discuss, review, and maintain. This code of conduct sets expectations for collaboration in issues, pull requests, code review, documentation, and project discussion.

## Expected Behavior

- Be direct, specific, and respectful when discussing code, UX, design, bugs, and tradeoffs.
- Critique the work, not the person doing the work.
- Assume good faith unless there is clear evidence otherwise.
- Keep feedback actionable. Explain the risk, affected behavior, or maintainability cost.
- Respect different skill levels, languages, time zones, and communication styles.
- Avoid sharing private information, credentials, unreleased security details, or personal contact information without permission.

## Unacceptable Behavior

- Harassment, threats, personal attacks, slurs, or degrading comments.
- Sexualized language or attention in project spaces.
- Publicly posting private information about another person.
- Repeatedly derailing technical discussion after maintainers have redirected the thread.
- Deliberately submitting malicious code, hidden tracking, credential leaks, or security regressions.
- Using the project issue tracker or pull requests for spam, impersonation, or unrelated promotion.

## Scope

This code applies to all project-maintained spaces, including repository issues, pull requests, discussions, documentation, code review, and any official community space that may be added later.

It also applies when a contributor represents the project publicly, such as by using an official project account, speaking for maintainers, or presenting project work as official.

## Reporting

If you need to report behavior, use the repository's available maintainer contact path. If no private contact path is published, avoid posting sensitive personal details publicly and contact the maintainer through their GitHub profile or repository-level options.

Reports should include:

- What happened.
- Where it happened.
- Who was involved.
- Any links, screenshots, logs, or timestamps that help maintainers verify the issue.

## Enforcement

Maintainers may take any action needed to protect project contributors and users, including:

- Clarifying expectations in the thread.
- Editing or hiding comments where the platform allows it.
- Closing, locking, or redirecting discussions.
- Rejecting contributions.
- Temporarily or permanently blocking participation.

Enforcement decisions should be based on the behavior, its impact, and the risk to the project community. Maintainers should avoid exposing private reporter details unless required by platform policy or law.

## Security Reports

Do not publicly disclose exploitable vulnerabilities before maintainers have a reasonable chance to review and fix them. If the repository does not publish a dedicated security contact, contact the maintainer privately through available GitHub channels and include enough detail to reproduce the issue.
